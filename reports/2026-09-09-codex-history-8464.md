# Codex 0.153.4 history compatibility — 2026-09-09

Reference snapshot for [investigation #8464](https://github.com/kamp-us/phoenix/issues/8464).
**Result: conditional support, not blanket pagination failure or full parity.** The packaged
local store supports nonempty legacy history and projected paginated history. A new durable
paginated thread without a metadata row refuses history reads. A discovered nonempty paginated
rollout without its item projection can instead return misleading successful empty history.
Neither result may become an empty Tuval transcript by policy.

allocation seed. That main contains [PR #8600](https://github.com/kamp-us/phoenix/pull/8600), merged

is therefore no longer current: [the Codex sibling exists](../apps/tuval/src/codex/CodexAiAgent.ts).
This investigation changes no production code, migration, runtime, settings or product policy.

The current [TuvalAiAgent contract](../apps/tuval/src/ai-agent/service/TuvalAiAgent.ts) includes
`sessionTranscript` as well as backend-owned `page` and terminal-session resume. A read-only
transcript lookup must not secretly resume a session. Missing, unreadable and genuinely empty
history are different answers. These obligations, not the presence of generated request types,
are the integration test.

### Safety correction after the first probe

C demonstrated that credential-free `thread/start` may attempt a websocket prewarm. The versioned
[startup implementation](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core/src/session_startup_prewarm.rs#L185-L225)
checks `responses_websocket_enabled`; its
[client prewarm](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core/src/client.rs#L1954-L2006)
uses `warmup=true`, documented and implemented as `generate=false`, not inference. C observed
handshake rejection, no successful generated output. It was **not a network-isolated run**.

To avoid repeating even this prewarm, A/B use a new provider configuration with websockets off,
not a fake endpoint or server. Built-in provider entries cannot generally be overridden
([merge function](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/model-provider-info/src/lib.rs#L546-L594)),
so pretending an `openai.supports_websockets=false` override worked would be unsafe. The explicit
probe provider changes model transport configuration, not the history store or execution harness.
No private credentials, sessions, user settings or model work were used. Empty stderr in A/B is
not a packet-capture proof of no ancillary networking.

## Source reconciliation

The versioned [README history contract](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/README.md#L660-L720)
and [thread processor](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/src/request_processors/thread_processor.rs)
are consistent with the observed conditional behavior:

1. **Store capability is not per-thread readiness.** New durable threads default to paginated
   when `supports_paginated_history_lists()` is true (thread processor, lines 1419–1422).
   [LocalThreadStore](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/thread-store/src/local/mod.rs#L597-L611)
   answers true when `state_db.is_some()`. The ordinary
   [local-store constructor](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core/src/thread_manager.rs#L380-L415)
   selects that store, not the unsupported defaults of the abstract trait.
2. **The same store can refuse individual reads.**
   [Per-thread validation](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/thread-store/src/local/thread_history/read.rs#L176-L203)
   returns `Unsupported` when the state DB is absent, the metadata row is absent, or that row is
   legacy. A/B's `fresh/*/before-read`, `after-read` and `after-fresh-exit` database snapshots
   contain **zero thread rows**, although the state DB exists. That is the exact missing-row
   branch behind these fresh refusals, not evidence that the entire packaged store lacks support.
3. **Read persistence is not metadata/projection readiness.** The live paginated includeTurns
   path persists and calls `paginated_thread_full_turns` (thread processor, lines 2998–3016).
   The named `list_turns` refusal propagates as `-32601`. Item-list mapping instead spells
   `thread/items/list is not supported yet` (lines 3384–3427). The legacy history loader uses the
   separate `not materialized yet` mapping (lines 5758–5806).
4. **Restart is a different state.** Fresh paginated includeTurns requests leave metadata-only
   rollouts on disk. On restart, [rollout metadata backfill](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/rollout/src/metadata.rs#L295-L345)
   discovers them; A/B then show the two paginated metadata rows and genuinely empty reads/pages.
   Fresh legacy leaves no rollout and becomes a missing unloaded session. Restart is an observed
   transition, not an integration retry recommendation.
5. **Metadata backfill is not an item projection.** For the nonempty JSONL-only paginated
   fixtures, metadata rows exist but projection checkpoints do not. The
   [read implementation](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/thread-store/src/local/thread_history/read.rs#L95-L173)
   pages projection tables; the persisted includeTurns path delegates there (thread processor,
   lines 2887–2922). Both return empty results in this state. The
   [live-writer resume path](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/thread-store/src/local/live_writer.rs#L145-L178)
   materializes the rollout into SQLite. After resume, checkpoints reach ordinal 15 and all four
   messages become readable. No store downgrade or legacy migration occurred.

The old README reference was byte-identical to the freshly fetched versioned README. All five
old request-type references matched newly generated **experimental** bindings. Nonexperimental
generation omits `historyMode`; it was not evidence of a binary mismatch. Schemas alone were never
used to mark a matrix cell successful.

## Fixtures and expected content

A/B each construct three independent `source:"cli"` JSONL fixtures, with IDs ending `001`, `002`
and `003`. They represent default-selected paginated, explicit legacy and explicit paginated
respectively. **Default is a new-thread selection, not a third on-disk format**: the fixture writer
uses the historyMode returned by that run's actual `thread/start`. These are synthetic
terminal-style records, not sessions produced by the terminal UI or a model.

The construction follows public versioned
[rollout test helpers](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/tests/common/rollout.rs),
[nonempty paginated test setup](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/tests/suite/v2/thread_read.rs#L500-L605),
[legacy append helpers](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/tests/suite/v2/thread_read.rs#L2088-L2121),
[SessionMeta](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/protocol/src/protocol.rs#L3031-L3169)
and [ordinal rules](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/rollout/src/ordinal.rs#L23-L50).
No upstream mock endpoint or model-generating test was run. Response-item records supply synthetic
model-visible message history; legacy display events and paginated item-completed records supply
transcript history. A/B preserve the complete fixture lines before resume mutates store state.

| Order | Turn | Text | Expected paginated item ID | Observed legacy item ID |
| --- | --- | --- | --- | --- |
| 1 | turn-1 | `fixture user 1` | user-1 | item-1 |

## Integration conclusion and limits

1. **Legacy:** a nonempty synthetic CLI-style legacy session can be listed, read, resumed and
   turn-paged without generation. Item pagination remains unsupported. The existing
   [Codex store reader](../apps/tuval/src/codex/store.ts) uses full `thread/read`, so native
   item-list support is not a prerequisite for that implementation. Fresh legacy unmaterialized
   state is still a named refusal; selecting legacy alone is not proof of history parity.
2. **Paginated:** the same packaged local store supports full history, full/metadata resume,
   initial-page resume and multi-page turns/items **when projection is present**. Preserve wire
   item identity and restore oldest-first ordering at Tuval's page boundary. Full-history
   includeTurns is deprecated upstream; successful fixture reads do not make it a permanent API.
3. **Read-only lookup remains unresolved for unprojected history.** `sessionTranscript` cannot
   satisfy its contract by attaching/resuming merely to warm a projection. Nor may it trust Z as
   legitimately empty. The source/fixture evidence establishes a separate readiness problem,
   filed immediately as [#8666](https://github.com/kamp-us/phoenix/issues/8666). No production fix,
   forced migration, SQLite manipulation or silent fallback is introduced here.
4. **Failure identity matters.** UT/UI indicate unavailable pagination, U indicates a fresh
   unmaterialized session, and N/R establish missing/unloaded history in these controls. Preserve
   useful detail through named store-unreadable/session-not-found failures; do not infer absence
   from `-32601`. Metadata omission and excludeTurns omission must never be graded as empty history.
5. **No broad terminal or model parity claim.** These public-source-derived `source:cli` fixtures
   prove the packaged history parser and store paths, not the terminal UI writer or model
   continuation. Paid/live turns, private sessions, authenticated stores, other CLI versions and
   OS builds, remote/in-memory stores, damaged databases, real tool/media/compaction/fork/revert
   histories, backwardsCursor navigation and concurrent writer races are untested. They were
   outside this bounded credential-free two-turn investigation, not inferred successes. No
   runtime rebuild/upgrade was attempted. Untouched start-only restart and empty-restart
   metadata/initial-page resume remain untested as specifically noted above.

Builder validation: `fabrika build check --surface prose` passed all six changed Markdown files
with no unvalidated files. `node --check` accepted the published driver. A separate read-back of
both published traces checked their hashes, all 448 request/response pairs, eight clean process
exits and 66 content/order/cursor assertions, including the expected unprojected-empty anomaly.
These are builder checks, not independent review or model-parity evidence.

All five investigation criteria are evidenced here: build/config/source identity, the operation
matrix, nonempty provenance/order and setting independence, a contract-bound integration
conclusion, and the safety record. This completes the **investigation deliverable**, not all Codex
work or #8666. The report PR still requires independent text review and normal CI/ship gates;
issue closure is not performed by this build lane.
