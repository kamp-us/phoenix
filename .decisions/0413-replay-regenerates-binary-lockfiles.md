# 0413 — A replay regenerates a merge=binary lockfile through a declared command, never any other binary file

**What this decides:** when `lane integrate` replays an epic child and the only thing that collides
is a lockfile the repo marks `merge=binary`, the replay rebuilds that lockfile with a command the
repo declares and keeps going, instead of parking the lane.

## Context

`lane integrate`'s replay (`assemblyReplay.onCollision: on`) resolves a collision only when every
hunk is a plain keep-both. A lockfile marked `merge=binary` in `.gitattributes` (for example
`pnpm-lock.yaml`) has no conflict markers, so the keep-both reader refused it and the lane parked
`REPLAY-COLLIDED` on `--cause replay-conflict`. Clearing it took a person or a builder round, only to
regenerate a file the package manager can always rebuild from the merged manifests. This was seen on
a downstream repo running fabrika-cli 0.7.0.

The founder ruled yes on [#9867](https://github.com/kamp-us/phoenix/issues/9867) in
[this ruling comment](https://github.com/kamp-us/phoenix/issues/9867#issuecomment-5851529523): a
replay that collides only on a `merge=binary` lockfile regenerates it instead of giving up.

The ruling names the repo's `dependencyReconciler` as the route. That key's command is the
fail-closed install (`pnpm install --frozen-lockfile`), which refuses to write a lockfile, so
regeneration needs a second declared command that is allowed to write one.

## Decision

**A replayed pick whose every unmerged path is a declared lockfile that `.gitattributes` marks
`merge=binary` is regenerated by the repo's declared `assemblyReplay.lockfileRegenerator` command,
staged, and continued; every other collision refuses exactly as before.**

- The command and the lockfile paths it owns live in `.fabrika.jsonc` as
  `assemblyReplay.lockfileRegenerator: {"command": [...], "lockfiles": [...]}`. Nothing is
  hard-coded, and the shipped value is `null`.
- A path qualifies only when it is in `lockfiles` **and** `git check-attr merge` answers `binary`
  for it. One unmerged path that does not qualify sends the whole pick to the keep-both judgment,
  which refuses the lockfile as it always did.
- The command runs in the assembly worktree. It may change the lockfiles and no other tracked file.
  A command that fails, cannot start, or writes anything else abandons the replay with a refusal
  that names the command and the lockfile, and the seat is put back as on every replay refusal.
- A replay that regenerated a lockfile still records `reReview: "required"`, and its event lists
  the file under `regenerated`. The lockfile rides in the child's replayed range, so the review
  round grades it with everything else.
- The post-merge `reconcile` step in `lane integrate` is unchanged. It still runs the frozen
  install and still refuses on exit 43 when that install rewrites a tracked file. The regenerated
  lockfile is already committed, so a correct regeneration leaves that install nothing to rewrite.
- **`assemblyReplay` now names a command fabrika spawns, so it moves into
  [ADR 0398](0398-machine-local-config-layer.md) rule 5's permanently ineligible spawn-command
  class.** 0398 filed `assemblyReplay` under the weaker "ineligible by default" bar because none of
  its fields ran anything. `lockfileRegenerator.command` is an argv fabrika runs in the assembly
  worktree mid-integrate, beside `codeValidators`, `workflowValidators` and `dependencyReconciler`.
  Eligibility is declared per key group, so `assemblyReplay` is barred whole from the machine-local
  config layer, the way `parkCause` is, and no later record may admit it locally. This amends 0398's
  classification of that one key. Nothing else in 0398 changes.

**Banned.**

- Regenerating any binary file that is not a declared lockfile.
- Regenerating when any non-lockfile path also collides.
- Loosening `reconcile`'s fail-closed check to let a replay through.

## Consequences

A lockfile-only collision no longer costs a builder round and a person. The price is that a
regenerated lockfile reaches the assembly branch before review grades it. The re-review the replay
already owes, the frozen install, and the code validators are what catch a bad one. A repo that
declares nothing keeps today's refusal byte for byte.
